# MiniMax H3 提示词工程技巧

> 本文以 MiniMax H3 官方仓库 README、官方 Base Prompt Guide、官方 `h3-prompt-writing` Skill 和官方 Ref2VA Guide 为依据。第 21–26 章按 2026-08-31 获取的官方文档逐节完整覆盖其有效信息；固定字段、标签、指令行、时间格式和命令保留官方写法。标为“工程建议”或“原理推导”的内容，是在官方结构之上总结出的生产经验，不代表 MiniMax 官方承诺。

## 1. Skill 的目标

本 Skill 不只是“把描述写得更华丽”，而是把用户意图编译成 H3 更容易执行的**多模态时序规格**。最终 Prompt 应同时回答以下问题：

1. 这是哪一种生成模式？
2. 哪些素材是角色参考，哪些是关键帧，哪些是运动或音色参考？
3. 视频从什么状态开始，经过什么可观察变化，最后停在什么状态？
4. 每个镜头何时开始，为什么切换？
5. 谁在说话，台词是什么语言，口型属于谁？
6. 环境声、动作声、对白、画内音乐和画外配乐分别属于哪一层？
7. 哪些外观、空间、物体状态和声音关系必须保持不变？
8. 视频时长能否容纳这些动作和台词？

高质量 H3 Prompt 的本质是：

```text
自然语言需求
→ 任务模式识别
→ 参考素材角色分配
→ 时间轴与状态机
→ 官方 Prompt 结构
→ 生成参数
→ 视听验收
```

## 2. 适用场景

在以下任务中启用本 Skill：

- 文生音视频：T2VA
- 首帧图生音视频：I2VA
- 首尾帧图生音视频：FL2VA
- 尾帧图生音视频：L2VA
- 多图片、多视频、多音频的全参考生成：Ref2VA
- 需要原生对白、旁白、环境声、动作音效或配乐的短片
- 需要固定角色、服装、场景、道具和镜头轴线的系列视频
- 需要把长剧本拆成多个 4–15 秒 H3 片段
- 需要设计 I2V 链式衔接、真实尾帧接力和发布前 QA

不应把本 Skill 当作：

- 精确排版、字幕制作或 Logo 设计工具
- 确定性的角色绑定系统
- 帧级视频编辑器
- 专业配音软件或声纹克隆工具
- 传统超分模型的替代品

H3 是生成模型。Prompt 能提高遵循率，但不能把概率生成变成绝对确定的渲染程序。

## 3. 官方能力边界速查

根据官方仓库当前说明：

| 项目 | 官方规格 |
|---|---|
| 单次输出时长 | 4–15 秒 |
| 帧率 | 24 FPS |
| 输出音频 | 32 kHz 立体声 |
| 常见画幅 | 21:9、16:9、4:3、1:1、3:4、9:16 等 |
| Base 输出 | 以 768p 为主要基准 |
| 2K | 官方完整系统通过 H3-Regenerate-2K 再生成，不等同于普通插值放大 |
| 稳定对白语言 | 中文、英语、日语、韩语、法语、德语、意大利语、西班牙语、葡萄牙语、俄语、阿拉伯语等 |
| FL2VA 条件 | 0、1 或 2 张图，分别对应 T2VA、I2VA/L2VA、FL2VA |
| Ref2VA 图片 | 最多 9 张 |
| Ref2VA 视频 | 最多 3 段，每段 2–15 秒，总时长不超过 15 秒 |
| Ref2VA 音频 | 最多 3 段，每段 2–15 秒，总时长不超过 15 秒 |
| Ref2VA 混合素材 | 所有输入文件合计最多 12 个 |

### 3.1 H3 三层系统

官方把完整系统描述为三部分：

1. **H3-Context-IR**：理解自由形式的文本、图片、视频和音频关系，把它们整理成 H3 更容易消费的上下文中间表示。
2. **H3-Base**：根据上下文联合生成视频 latent 与音频 latent，再分别解码为视频和立体声音频。
3. **H3-Regenerate-2K**：把 Base 视频与原始上下文再次交给 H3，以 in-context 方式重新生成高分辨率细节。

### 3.2 为什么 Prompt 要像“中间表示”

H3 不是只读取一串风格词。它需要同时理解时间、空间、角色、声音和参考素材之间的关系。官方 Prompt Guide 的结构化字段，本质上是在手工近似 H3-Context-IR：

- 标签解决“这是谁、来自哪个素材”；
- Shot 与时间点解决“何时发生”；
- 状态变化解决“前后如何连接”；
- 声音分层解决“哪个声音属于场景，哪个只给观众听”；
- retention 关系解决“参考素材究竟要复制什么”。

因此，Prompt 的核心不是词藻，而是**关系清晰、时间可执行、状态无矛盾**。

## 4. 总体工作流

### Step 1：识别输入模式

按以下决策树选择模式：

```text
没有图片、视频、音频参考？
└─ 是 → T2VA

只有一张图？
├─ 图是第 0 秒 → I2VA
└─ 图是视频结尾 → L2VA

两张图分别锁定开头和结尾？
└─ 是 → FL2VA

需要多图角色、参考视频、音色、动作、场景或编辑关系？
└─ 是 → Ref2VA
```

不要因为“有一张角色参考图”就机械地选择 I2VA。若图片只定义人物身份、并不是第 0 秒的具体画面，应使用 Ref2VA 的 `<Subject N>` 关系。

### Step 2：建立素材角色表

生成 Prompt 前，先在脑中或工作文件中建立素材台账：

| 素材 | 角色 | 允许继承 | 不应继承 |
|---|---|---|---|
| Picture 1 | 主角身份 | 脸、发型、服装、比例 | 背景文字、平台水印 |
| Picture 2 | 场景参考 | 建筑、布局、色彩 | 图片中的路人身份 |
| Video 1 | 运镜参考 | 镜头路径、剪辑节奏 | 原视频人物和品牌 |
| Audio 1 | 音色参考 | 音色、语速、情绪 | 原台词内容 |

如果一个素材同时承担多个职责，必须明确每个职责；如果职责冲突，应拆分或决定优先级。

### Step 3：先写时间轴，再写美术描述

推荐先形成最小时间轴：

```text
0.0–4.5 秒：建立人物和问题
4.5–10.0 秒：执行核心动作
10.0–15.0 秒：结果、反应和结尾锚点
```

再给每一段补充：

- 当前景别和构图
- 主体位置与朝向
- 动作起点和终点
- 摄影机运动
- 同步声音
- 台词和口型
- 需要保持的状态

### Step 4：编译为官方结构

Base 模式使用三段式；Ref2VA 使用六段式。字段名、字段顺序、标签和时间格式不要自行发明。

### Step 5：做静态检查

生成前检查：

- 所有时间点严格递增并落在总时长内；
- Shot 1 不写时间戳；
- 后续 Shot 使用 `[Shot N] At 00:SS.mmm, ...`；
- 所有说话人 ID 全程稳定；
- 台词只出现一次；
- 对白只放在 `<d>` 内；
- 环境声、动作声和配乐没有重复或冲突；
- 关键帧标签和素材数量一致；
- 动作数量符合 4–15 秒的物理承载能力。

### Step 6：生成后做视听 QA

Prompt 通过不代表结果通过。至少检查：

- 真实帧数、时长、帧率和音轨；
- 首帧/尾帧是否真正命中；
- 人脸、服装、道具数量是否漂移；
- 口型是否属于正确角色；
- 台词是否错读、重复、截断或串台；
- 是否意外生成字幕、Logo、乱码或多余人物；
- 是否有冻结帧、跳帧、黑帧、穿模或动作逆序；
- 剪辑点前后空间和声音是否连续。

## 5. Base 模式的官方三段式

T2VA、I2VA、FL2VA、L2VA 的正文固定由以下三部分构成：

```text
integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

### 5.1 `integrated_multimodal_description`

这是主时间轴，包含：

- 视觉风格
- 初始构图
- 人物和物体
- 场景与灯光
- 动作和反应
- 镜头切换与运镜
- 说话人、对白、歌唱
- 与画面时间严格同步的画内声音

原则：这里的每个细节都应该能被观众**看见或听见**。不要把项目管理说明、模型参数、验收口号和抽象愿望混入正文。

### 5.2 `overall_soundscape`

用 1–4 句英文连续描述全片的：

- 环境底噪
- 风雨、交通、机器、室内混响
- 脚步、衣料、碰撞、开门、物体操作
- 呼吸、笑声、喘息等非语言人声

不要在这里重复完整对白、歌词或画内音乐。

### 5.3 `non_diegetic_music`

描述只给观众听、角色听不到的配乐。应具体写：

- 乐器
- 速度
- 节奏
- 强弱变化
- 进入和退出时机

不要只写 `epic`、`emotional`、`beautiful`。如果没有画外配乐，写：

```text
non_diegetic_music: N/A
```

## 6. 四种 Base 模式

## 6.1 T2VA：文本生成完整音视频

### 官方定义

没有关键帧输入，由文本建立完整视听时间轴。

### 推荐状态结构

```text
初始世界状态
→ 动作触发
→ 可见变化
→ 结果或反应
```

### 模板

```text
integrated_multimodal_description: [Shot 1] Live-action, cinematic, ...
[Shot 2] At 00:05.000, the camera cuts to ...

overall_soundscape: ...

non_diegetic_music: ...
```

### 适用技巧

- Shot 1 必须把人物、场景、光线和初始构图说清楚。
- 角色第一次出现时一次性建立稳定身份，后续用同一描述或固定称呼延续。
- 每个镜头应承担新信息；只有景别小变化时，优先运镜而不是切镜。
- 15 秒内不要同时要求多个地点、复杂打斗、长对白和连续变装。

## 6.2 I2VA：首帧向前发展

### 官方固定首行

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
```

这句话必须位于 Prompt 第一行，其后空一行，再写三段式正文。

### 推荐状态结构

```text
首帧锚点
→ 动作开始
→ 连续发展
→ 结果或反应
```

### Prompt 要点

1. 先承认 `<Picture 1>` 已经给出了人物、构图和场景。
2. 描述从图片之后发生的变化，而不是用新形容词重新设计图片。
3. 锁定人物身份、服装、颜色、关键道具和空间关系。
4. 首帧中不存在的内容，必须说明它如何进入画面。

### 工程建议：真实尾帧链式接力

长视频可把上一段真实最后一帧作为下一段 `<Picture 1>`：

```text
Clip N 的真实最后帧
→ Clip N+1 的 I2VA 首帧
```

优点：

- 构图和人物位置连续；
- 不需要额外重绘桥接图；
- 转场关系最直观。

风险：

- 尾帧中的模糊、字幕、闭眼、穿模也会被继承；
- 片尾动作若仍高速运动，下一段容易抖动或突变；
- 视频编码最后帧不一定是最适合作为叙事锚点的帧。

生产上可提供两种策略：

- **真实尾帧模式**：严格使用最后一帧，连续性强，但会继承瑕疵。
- **稳定尾帧模式**：在最后若干帧中选择清晰、无遮挡、动作趋稳的帧，质量更稳，但不再是绝对最后帧。

应由项目需求明确选择，不要在没有说明时混用。

## 6.3 FL2VA：首尾帧之间建立可见路径

### 官方固定首行

```text
How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.
```

`N` 是实际最后一个镜头编号；`S.SS` 是精确到两位小数的有效时长。

### 推荐状态结构

```text
首帧状态
→ 可观察中间变化
→ 差异逐步缩小
→ 命中尾帧状态
```

### 核心原则

- 不要只把两张图分别描述一遍；重点是“中间如何发生”。
- 官方倾向单镜头插值；只有用户明确需要时才使用多镜头。
- 尾帧不是灵感参考，而是最终必须到达的状态。
- 动作路径必须物理可行，例如手从桌面移动到门把手，而不是瞬间出现在终点。

### 适合 FL2VA 的动作

- 开门、合伞、转身、坐下、递物
- 表情从平静变为惊讶
- 灯光从白天过渡到夜晚
- 产品从闭合状态变为展开状态

### 不适合一段 FL2VA 强行完成的任务

- 两张图是完全不同地点、不同人物、不同镜头轴线；
- 首尾物体拓扑差异过大；
- 中间需要多次硬切和复杂叙事；
- 需要精准文字逐字变化。

## 6.4 L2VA：从合理前态收敛到尾帧

### 官方固定首行

```text
How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.
```

### 推荐状态结构

```text
合理前态
→ 明确动作路径
→ 最后镜头逐步收敛
→ 命中尾帧
```

### 常见用途

- 片尾定格
- 产品最终展示姿态
- 角色最后站位
- 预设 Ending Card 之前的动作收束

### 关键点

- `<Picture 1>` 属于最后的 `[Shot N]`，不是天然属于 Shot 1。
- 前态必须与尾帧在物理和叙事上兼容。
- 最后几秒要减少新信息，让模型有足够时间收敛到目标画面。

## 7. Shot 与时间轴语法

## 7.1 Shot 1 不写时间戳

正确：

```text
[Shot 1] Live-action, cinematic, a medium shot frames ...
```

不推荐：

```text
[Shot 1] From 00:00.000 to 00:05.000 ...
```

## 7.2 后续 Shot 使用严格递增的切点

```text
[Shot 2] At 00:04.500, the camera cuts to ...
[Shot 3] At 00:10.000, the shot cuts to ...
```

时间点必须：

- 严格递增；
- 小于视频总时长；
- 与对白和动作所需时间匹配；
- 不在同一瞬间要求多个冲突事件。

## 7.3 什么情况值得切镜

切镜应带来至少一种新信息：

- 新主体
- 新空间
- 新状态
- 新视角
- 新时间阶段
- 关键反应

若只是从中景轻微变近，优先使用 `Push In` 或 `Zoom In`，不要浪费一个 Cut。

## 7.4 15 秒信息预算

以下是工程启发式，不是官方硬限制：

- 单镜头：适合产品动作、情绪表演、首尾帧过渡。
- 2 个镜头：通常最稳定，适合“建立—结果”。
- 3 个镜头：适合“建立—行动—反应”。
- 4 个以上镜头：容易出现身份漂移、空间断裂和声音拥挤。

每个镜头最好只有一个主要动作目标。多个次动作必须服务于同一目标。

## 8. 摄影机语言

官方把运镜拆成三个维度：

```text
运动类型 + 幅度 + 速度
```

### 8.1 官方常用运动类型

| 英文 | 中文含义 | 适用场景 |
|---|---|---|
| `Zoom In / Zoom Out` | 变焦推近/拉远，机位不动 | 强调细节、制造压缩感 |
| `Push In / Pull Out` | 摄影机物理前移/后移 | 情绪推进、揭示空间 |
| `Pan Left / Pan Right` | 固定机位水平摇镜 | 跟随横向信息 |
| `Truck Left / Truck Right` | 摄影机水平平移 | 保持距离的横向运动 |
| `Tilt Up / Tilt Down` | 固定机位垂直摇镜 | 从脚到脸、从地面到天空 |
| `Pedestal Up / Down` | 整体机位垂直移动 | 高度变化、空间揭示 |
| `Arc Shot` | 围绕主体弧线运动 | 英雄展示、关系变化 |
| `Tracking Shot` | 跟随移动主体 | 行走、奔跑、追逐 |
| `Static Shot` | 机位和镜头保持静止 | 数字人、产品、稳定对白 |
| `Shake Slightly / Strongly` | 轻微/强烈震动 | 冲击、灾难、主观紧张 |
| `POV` | 主观视角 | 代入、扫描、观察 |
| `Roll Clockwise / Counterclockwise` | 绕镜头轴旋转 | 失衡、梦境、转场 |

幅度：

```text
with small amplitude
with large amplitude
```

速度：

```text
at slow speed
at fast speed
```

### 8.2 写成自然动作句

推荐：

```text
The camera pushes in with small amplitude at slow speed toward the letter in her hands.
```

不推荐把多个标签堆在句尾：

```text
cinematic, push in, zoom, pan, orbit, handheld, fast, epic
```

### 8.3 运镜冲突

以下组合容易产生不可执行或随机结果：

- 同一时间既 `Static Shot` 又 `Tracking Shot`；
- 摄影机向左平移，同时要求主体始终固定在画面最左边，却没有补偿逻辑；
- 一秒内同时推、拉、摇、环绕和翻滚；
- 硬切后仍要求上一镜头连续的单一物理运镜。

工程原则：每个时间段只指定一个主运镜，次级手持感只作为微小风格。

## 9. 人物、物体和场景连续性

### 9.1 建立角色锁定卡

角色第一次出现时，优先写稳定且可观察的特征：

- 年龄段和性别表达
- 脸型、肤色、发型
- 身材比例
- 服装版型和颜色
- 固定配饰或标志
- 当前姿态和屏幕位置

示例：

```text
a 24-year-old East Asian man with fair natural skin, short carefully styled black hair, a lean build, and a dark navy open-collar shirt
```

不要频繁更换同一人物的形容词。同义词对人类相近，对模型可能意味着重新采样身份。

### 9.2 把连续性写成状态，而不是口号

弱：

```text
Keep everything consistent.
```

强：

```text
He remains on the right side of the desk, wearing the same navy shirt; the monitor stays on his left, and the warm window light continues from camera left.
```

### 9.3 对象状态机

复杂物理动作应拆成明确状态：

```text
门关闭
→ 手接近把手
→ 手掌握住把手
→ 铰链方向旋转
→ 门完全打开
→ 手松开
```

这样比“人物自然打开冰箱门”更容易避免穿模、反向开门和手穿过门板。

### 9.4 屏幕轴线

系列视频应记录：

- 人物在左还是右；
- 面朝哪个方向；
- 视线指向哪个对象；
- 主光来自哪侧；
- 门、窗、显示器和桌子的相对位置。

跨镜头若改变轴线，要写明切到反打或新视角，不要让模型猜。
